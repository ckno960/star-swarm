# NPC 헌트 (프로토타입)

2~8명이 NPC 사이에 섞여 NPC인 척하다가, 바로 옆 칸의 진짜 플레이어를 찾아 찌르는 픽셀 게임입니다.

## 규칙

- 맵은 10×10(100칸)이고, 한 칸에 한 명만 설 수 있습니다. 캐릭터는 플레이어와 NPC를 합쳐 항상 24명입니다.
- 모두 0.4초(1틱)마다 한 칸씩 움직입니다. 플레이어 입력도 NPC와 같은 박자로 처리되기 때문에 움직이는 타이밍으로는 구분할 수 없습니다.
- **찌르기는 바라보는 방향으로 4방향 중 바로 옆 한 칸**만 됩니다. 막힌 쪽으로 움직이면 방향만 바뀌므로, 옆 사람 쪽으로 한 번 부딪친 뒤 찌르면 됩니다. 한 번 찌르면 3틱을 기다려야 다시 찌를 수 있습니다.
- **목숨은 3개**입니다.
  - 플레이어에게 찔리면 목숨이 1개 줄고, 다른 칸에서 새 캐릭터로 부활합니다.
  - NPC를 찌르면 **찌른 사람**의 목숨이 1개 줄어듭니다.
  - 찔린 NPC도 똑같이 다른 칸에서 다시 나타납니다. 그래서 누가 부활했는지만 보고는 플레이어인지 알 수 없습니다.
- 목숨을 모두 잃으면 탈락합니다. **최후의 1인**이 승리하고, 마지막 둘이 동시에 쓰러지면 무승부입니다.
- 게임 도중 나간 플레이어의 캐릭터는 NPC가 이어받습니다.

## 모드

| 모드 | 방법 |
|---|---|
| 친구와 하기 | [방 만들기]를 누르면 4자리 코드가 나옵니다. 친구가 코드로 입장하고, 2명 이상 모이면 방장이 시작합니다. 게임이 끝나면 같은 멤버로 로비에 돌아갑니다 |
| 빠른 매칭 | 모르는 사람과 자동으로 방이 잡힙니다. 2명이 모이면 15초 카운트다운이 시작되고, 8명이 차면 바로 시작합니다. 게임이 끝나면 방이 해산됩니다 |

## 실행

```
npm install
npm start        # http://localhost:8080 (포트는 PORT 환경 변수로 변경)
npm test         # 게임 로직 + 서버 테스트
```

같은 와이파이에 있는 휴대폰에서는 `http://<컴퓨터 IP>:8080`으로 접속합니다.

## 구조

```
game.js           → 순수 게임 로직 (이동, 찌르기 판정, 목숨, 승리). 서버만 사용
server.js         → HTTP(client/ 제공) + WebSocket. 방 관리, 틱 루프, 상태 전송
client/index.html → 메뉴/로비/게임 화면, 캔버스 픽셀 렌더링, 키보드·터치 입력
game.test.js, server.test.js
```

## 정체를 숨기는 방법

- 서버만 누가 플레이어인지 압니다. 클라이언트가 받는 캐릭터 정보는 `{id, x, y, dir, skin}`뿐이고, 플레이어와 NPC가 똑같은 모양입니다.
- id는 무작위 값이고 id 순으로 정렬해서 보냅니다. 각 클라이언트는 자기 id 하나만 받습니다.
- 매 틱 이동 순서를 섞습니다.
- 탈락해도 그 자리에 NPC가 새로 생겨서 전체 수가 줄지 않습니다.
- 공격 결과(헛방, NPC였음, 쿨다운)는 찌른 사람에게만 보냅니다. 다른 사람에게는 쓰러진 자리만 보입니다.

## 통신 메시지

```js
// 클라이언트 → 서버
{ t: 'create', name }           // 친구 방 만들기
{ t: 'join', code, name }       // 코드로 입장
{ t: 'quick', name }            // 빠른 매칭
{ t: 'start' }                  // 방장만
{ t: 'leave' }
{ t: 'move', dir }              // 'up' | 'down' | 'left' | 'right'
{ t: 'attack' }                 // 바라보는 방향 한 칸

// 서버 → 클라이언트
{ t: 'lobby', code, mode, isHost, players, startsIn, min, max }
{ t: 'start', size, tickMs, lives, players }
{ t: 'state', tick, ents, bodies, alive, me: { id, lives, cooldown, alive } }
{ t: 'event', kind, lives? }    // cooldown | miss | penalty | killPlayer | hurt | eliminated
{ t: 'over', winner, youWon }
{ t: 'left' } / { t: 'error', msg }
```

## 배포

WebSocket 서버가 계속 떠 있어야 하므로 GitHub Pages(정적 호스팅)에는 올릴 수 없습니다. Render, Fly.io, Railway 같은 곳에 Node 앱으로 올리고 시작 명령을 `npm start`로 지정하면 됩니다. 이 서비스들은 `PORT` 환경 변수를 자동으로 넣어 줍니다. 방 정보는 메모리에만 있으므로 서버 인스턴스는 1개로 둡니다.

## 아직 없는 것
